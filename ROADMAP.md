# Дорожная карта / Roadmap

Статус на версию 1.0.4. Порядок внутри версии — приоритет.

## 1.1.0 — надёжная работа на роутере
Цель: проект можно ставить на реальный роутер и не думать о нём.

- [ ] Проверка на живых роутерах (OpenWrt, Keenetic Entware): `nft -c` для сгенерированных правил, прогон с настоящим sing-box, фиксация результатов.
- [ ] Сборка `.ipk` (OpenWrt) и Docker-образа в CI и публикация вместе с бинарниками релиза (сейчас только бинарники).
- [ ] CI на GitHub Actions: `go vet` (linux/windows), тесты, сборка, проверка согласованности версии.
- [ ] Автоматический релиз по тегу `vX.Y.Z` (бинарники, контрольные суммы, `.ipk`, образ), чтобы тег не мог указать на дерево с другой версией.
- [ ] Загрузчик списков `.lst` (сейчас поддерживаются только `.srs` и `.json`), обновление списков по `update_interval`.
- [ ] IPv6: перехват трафика LAN и правила для IPv6.
- [ ] DNS: перенаправление клиентов на `127.0.0.42` для FakeIP (dnsmasq на OpenWrt), учёт `dont_touch_dhcp`.
- [ ] Мониторинг WAN (`enable_badwan_interface_monitoring`): перезагрузка при смене интерфейса. Поле есть в конфиге, логики нет.
- [ ] Автоматическая проверка обновлений компонентов (sing-box, nfqws, ciadpi) — настройки есть, реализации нет.

## 1.2.0 — управление и наблюдаемость
- [ ] Подключить `internal/api` (Clash-совместимый API) и веб-интерфейс: сейчас это неподключённый код и статичный прототип, LuCI обращается к несуществующему RPC.
- [ ] Реальная страница LuCI (OpenWrt); для Keenetic и MikroTik — встроенный веб-интерфейс сервиса.
- [ ] Подключить или удалить `internal/platform/*` (openwrt, keenetic, mikrotik) — сейчас мёртвый код.
- [ ] Определение страны узла (`detect_server_country`, фильтры `include/exclude_countries`).
- [ ] Прокси-транспорты, которых нет в sing-box (xhttp и др.): решение — отдельный провайдер или явная документация ограничений.
- [ ] Серверы `mtproto` и `tailscale` (сейчас только через `inbound_json`).
- [ ] Метрики и подробный статус узлов (задержка, выбранный узел, трафик).

## 2.0.0 — интеграция с Radar
Подключение к внешнему проекту и получение подписок через Telegram-бота Radar.

- [ ] Проработать протокол: как бот отдаёт подписки (ссылка, файл, API), способ аутентификации, лимиты устройств (HWID).
- [ ] Источник подписок «Radar» в конфиге (новый тип рядом с `subscription_urls`), привязка к секции.
- [ ] Привязка роутера к аккаунту в боте (одноразовый код), безопасное хранение токена.
- [ ] Периодическое обновление подписок из Radar, отображение квоты и срока действия.
- [ ] Команды CLI и, при необходимости, уведомления в бот (статус, ошибки обновления).
- [ ] Тесты с заглушкой сервера Radar, документация.

Открытые вопросы для 2.0.0: формат API бота, нужен ли отдельный сервис-мост, где хранится токен на роутере.
