# Дорожная карта / Roadmap

Статус: версия 1.0.5. Порядок внутри версии — приоритет. Версии 1.0.x — небольшие шаги, после каждого выходит релиз; при поиске ошибок выпускаются отладочные сборки (см. «Отладочные сборки»).

## Технический долг (сквозной, закрывается по ходу 1.0.x)
- [ ] Тесты для `core`, `firewall` (Linux), `process`, `byedpi`, `zapret`, `config`.
- [ ] Маскирование секретов в `hydravpn-router config` (ключи, токены, пароли).
- [ ] Единые окончания строк (`.gitattributes`, `.editorconfig`).
- [ ] Ротация и уровни логов под procd/systemd/Entware.

## 1.0.6 — CI, релизы, сети
- [ ] CI (GitHub Actions): `go vet` (linux/windows), тесты, сборка, проверка согласованности версии.
- [ ] Автоматический релиз по тегу: тег не может указать на дерево с другой версией.
- [ ] Сборка `.ipk` и Docker-образа и публикация вместе с бинарниками.
- [ ] Списки `.lst`, обновление списков по интервалу.
- [ ] IPv6 (перехват трафика LAN, правила).
- [ ] DNS-перенаправление клиентов для FakeIP (dnsmasq), учёт `dont_touch_dhcp`.
- [ ] Мониторинг WAN (`enable_badwan_interface_monitoring`) и проверка обновлений компонентов — в конфиге поля есть, логики нет.

## 1.0.7 — управление
- [ ] Подключить или удалить неподключённые `internal/api`, `internal/platform/*` и веб-интерфейс (LuCI и встроенный для Keenetic/MikroTik).
- [ ] Определение страны узла, фильтры по странам.
- [ ] Серверы `mtproto` и `tailscale`.
- [ ] Метрики и статус узлов (задержка, выбранный узел, трафик).

## 1.0.8 — совместная работа с приложением HydraVPN
Приложение: https://github.com/Chistovik92/HydraVPN
- [ ] Логирование всех операций и событий (структурированный журнал, доступ из приложения).
- [ ] Полное управление роутером из приложения: старт/стоп/reload, статус, выбор узла.
- [ ] Добавление подписок и серверов из приложения.
- [ ] Исследование способов подключения: из локальной сети роутера и извне (через интернет): аутентификация, TLS, ограничение по адресам, обратный туннель или облачный ретранслятор; выбор безопасного варианта.

## 1.0.9 — актуализация внешних компонентов
- [ ] Пошаговый обзор изменений во внешних проектах, на которых основана логика (sing-box, zapret, ByeDPI и др.): что нового, что стоит перенять, что сломает совместимость.
- [ ] Обновление настроек и стратегий по результатам обзора, тесты совместимости конфигов.

## 1.1.0 — оптимизация и обновление ядер
- [ ] Оптимизация кода (память, размер бинарника, время старта) без изменения поведения.
- [ ] Обновление версий sing-box и Xray без изменений в коде проекта: проверка совместимости по тестам конфигов, документирование поддерживаемых версий.

## 1.2.0 — проверка на живых роутерах
- [ ] OpenWrt и Keenetic (только через Entware: флешка или встроенная память): `nft -c` для сгенерированных правил, прогон с настоящим sing-box, фиксация результатов по моделям.
- [ ] Keenetic: проверка модулей ядра (`nft_tproxy`/`xt_TPROXY`), хук `/opt/etc/ndm/netfilter.d/` для восстановления правил после пересборки Netfilter.
- [ ] MikroTik (контейнер): готовый пример настройки RouterOS (mangle, маршрутизация в контейнер) и проверка на ARM/ARM64.

## Дальше (предложение)
- **1.3.0 — безопасность.** Аудит секретов и прав файлов, `govulncheck` в CI, подпись релизов, обновление бинарника с проверкой подписи.
- **1.4.0 — конфигурация.** Миграции `config_version`, резервные копии и откат конфигурации, импорт/экспорт, валидация с подсказками.
- **1.5.0 — устойчивость сети.** Несколько WAN и отказоустойчивость, приоритеты узлов, kill-switch по секциям.
- **1.6.0 — поддержка.** `hydravpn-router support-bundle` (журнал, статус, версии, без секретов), встроенная диагностика по шагам.

## 2.0.0 — интеграция с Radar
Подключение к внешнему проекту и получение подписок через Telegram-бота Radar.
- [ ] Протокол бота, аутентификация, лимиты устройств (HWID).
- [ ] Новый тип источника подписок в конфиге, привязка к секции.
- [ ] Привязка роутера к аккаунту (одноразовый код), хранение токена.
- [ ] Периодическое обновление подписок, квота и срок действия.
- [ ] CLI-команды, тесты с заглушкой сервера Radar, документация.

Открытые вопросы: формат API бота; где хранить токен на роутере.

## Отладочные сборки
Для поиска ошибок между релизами: предрелизы `vX.Y.Z-debug.N` (не помечаются как Latest, `install.sh` их не выбирает сам, только через `--version`). Включают `log_level: debug`, подробный журнал маршрутизации и подписок, `pprof` на localhost. Требуется доработка сравнения версий в `install.sh` для суффикса `-debug.N`.
