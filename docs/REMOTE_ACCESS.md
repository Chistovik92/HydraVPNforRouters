# Подключение к роутеру: из локальной сети и извне / Connecting to the router

Исследование способов, которыми приложение [HydraVPN](https://github.com/Chistovik92/HydraVPN) (Android) и другие клиенты управляют роутером через [Management API](API.md). Итог: что реализовано, что рекомендуется, что планируется.

## 1. Из локальной сети (реализовано, 1.0.7–1.0.8)

Приложение подключается к `http(s)://<адрес роутера>:<порт>` с токеном.

- Токен: `hydravpn-router api-token`, либо привязка одной командой: `hydravpn-router pair --host 192.168.1.1` печатает ссылку `hydravpn-router://…` (адрес, порт, токен, схема, отпечаток сертификата), которую приложение принимает при добавлении роутера. QR-код можно получить любым генератором из этой строки.
- По умолчанию доступ только из loopback и частных сетей (`api_allow`).
- Для HTTPS с самоподписанным сертификатом приложение должно **закрепить отпечаток** (SHA-256), который выдаёт `pair`; принимать любой сертификат нельзя.

## 2. Извне (из интернета)

| Способ | Плюсы | Минусы | Оценка |
|---|---|---|---|
| **A. VPN в домашнюю сеть** (WireGuard на роутере, Tailscale) → дальше как из LAN | Ничего не открывается наружу; шифрование и аутентификация уже есть; работает с существующими средствами | Нужен клиент VPN на телефоне; за CGNAT нужен Tailscale или похожее | **Рекомендуется** |
| **B. Проброс порта API на WAN** + TLS + токен + `api_allow` | Просто, без сторонних сервисов | Порт виден в интернете; нужен белый IP; риск при утечке токена; не работает за CGNAT | Допустимо только с TLS, длинным токеном, узким `api_allow` |
| **C. SSH-туннель** (`ssh -L 8088:127.0.0.1:8088 router`) | Не нужно ничего менять | Неудобно с телефона | Для администратора |
| **D. Обратное соединение (роутер → облако/ретранслятор)** | Работает за CGNAT, наружу ничего не открыто | Нужен посредник; его надо разработать и защитить | Планируется вместе с Radar (2.0.0) |
| **E. Telegram-бот как канал управления** | Только исходящие соединения; удобный интерфейс | Доверие к Telegram; ограниченный формат команд | Планируется (Radar, 2.0.0) |

### Рекомендация

1. Для домашнего использования: способ **A**. sing-box на роутере умеет Tailscale-эндпоинт (`servers: - protocol: tailscale`), либо используйте WireGuard роутера. API слушает LAN-адрес, приложение подключается по адресу роутера внутри VPN.
2. Если нужен прямой доступ: способ **B** только с `api_tls_cert`/`api_tls_key`, закреплением отпечатка в приложении, `api_allow` с конкретными адресами и уникальным токеном.
3. Для роутеров за CGNAT без VPN: способы **D/E** в рамках Radar (2.0.0).

## 3. Что уже защищает API

- токен (сравнение за постоянное время), генерация случайного 192-битного токена;
- фильтр адресов; ограничение перебора (10 ошибок в минуту на адрес → 429);
- TLS 1.2+ по желанию; предупреждение в журнале при работе без TLS на не-loopback адресе;
- аудит всех изменяющих запросов и отказов; секреты в ответах маскируются;
- изменения конфигурации атомарны, предыдущая версия сохраняется в `.bak`.

## 4. Что нужно для безопасного внешнего доступа (план)

- токены с ролями (только чтение / управление) и срок жизни, отзыв токена;
- взаимная TLS-аутентификация (клиентский сертификат приложения);
- ограничение по времени сессии и подтверждение опасных действий (restart, удаление секций);
- журнал входов, доступный в приложении (уже есть через `/api/v1/logs`).

## 5. Как приложение использует API

- Подписки/серверы: `POST /api/v1/subscriptions`, `/servers`, `/sections` — изменения применяются сразу.
- Узлы: `GET /api/v1/nodes`, `POST /api/v1/nodes/select`, `/nodes/test`.
- Наблюдение: `GET /api/v1/status`, журнал `GET /api/v1/logs` и поток `/api/v1/logs/stream`.
- Управление: `POST /api/v1/reload`, `/restart`, диагностика `/check/{name}`.

Стабильность: пути `/api/v1/*` не меняются в рамках 1.x; новые поля добавляются без удаления старых.
