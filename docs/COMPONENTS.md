# Внешние компоненты / External components

Сервис управляет внешними программами и следует форматам нескольких проектов. Этот документ фиксирует, с какими версиями проверялась работа, что изменилось в них и что из этого влияет на проект. Обзор обновляется по шагам при каждом выпуске; автоматическая сверка версий: `scripts/check-upstream.sh` и еженедельный workflow `Upstream` (создаёт issue при выходе новой версии).

Таблица версий — `docs/components.tsv` (источник для скрипта). Проверка версии sing-box на самом роутере: `hydravpn-router status` → `components`: `update_available` — вышла новая версия, `too_old` — установлена старше минимальной, `untested_newer` — установлена новее проверенной, `latest_untested` — последняя вышедшая новее проверенной ветки (major.minor), обновляться на неё — на свой риск. Версии с суффиксом (`1.13.0-beta.5`) считаются старше выпуска `1.13.0`. Запрос к GitHub идёт с CA-сертификатами Entware (на Keenetic другого хранилища нет); с `download_components_via_proxy` — через локальный mixed-прокси, а с `download_components_via_proxy_section` — через аутбаунд этой секции.

Скрипт проверяет все компоненты таблицы и сравнивает версии через `sort -V`. У Xray-core с июня 2026 все выпуски помечены pre-release, поэтому `releases/latest` отдаёт старый; для него берётся самый новый выпуск (список `ANY_RELEASE_REPOS` в скрипте). Workflow `Upstream` держит один открытый issue «Component updates available» и обновляет его, а не создаёт новый каждую неделю.

## Обзор (шаг за шагом), состояние на 1.0.9

### 1. sing-box — ядро прокси (обязательно)
- Проверено: **1.14.4** (последний стабильный на 2026-10-28; 1.14.4 — исправления и улучшения, без изменений формата); минимально поддерживается **1.12.0** (формат DNS-серверов с `type`, действия правил `sniff`/`hijack-dns`/`reject`).
- 1.13: NaiveProxy, улучшения `local` DNS, `preferred_by`, опции keep-alive; Tailscale-эндпоинт получил relay-опции. Совместимо, конфиг менять не требуется.
- 1.14: новая семантика неопределённых наборов правил (rule-set), опции DNS (`evaluate`, кэш, таймауты), `sniff` в pre-match, JSON Schema, множественные теги в rule-set, встроенный API-сервис sing-box. **Влияние:** генерируемый конфиг использует только опции, существовавшие в 1.12, и проходит `sing-box check` на 1.14. Что стоит перенять позже: JSON Schema для проверки конфига в тестах, `initial_path` для rule-set (кэш офлайн), таймауты DNS.
- Что перенимаем сейчас: ничего не меняем в коде (правило 1.1.0: обновление без изменения логики). Сервис предупреждает в журнале, если установлена версия новее проверенной.
- Известные ограничения: транспорты xhttp/kcp не поддерживаются sing-box (узлы пропускаются); эндпоинт Tailscale нужен сборке sing-box с поддержкой Tailscale, в Entware-сборках может отсутствовать.

### 2. zapret / zapret2 — десинхронизация DPI (опционально)
- Проверено: zapret **72.13**, zapret2 **1.0.6** (изменения: диссекция QUIC/TLS, `?`/`#` как конец домена в URL, ограничение winsize scale factor в conntrack nfqws2, правки blockcheck2; параметры запуска не менялись).
- Используются только документированные параметры `nfqws`/`nfqws2` (`--dpi-desync`, `--dpi-desync-fooling`, `--filter-tcp/udp`, `--new`; для zapret2 — Lua-стратегии `--lua-desync`).
- Влияние: стратегии по умолчанию в `internal/providers/zapret` — точка для обновления при изменении рекомендаций проекта; пользовательская стратегия задаётся `provider_options` секции.
- Проверить при обновлении: пути Lua-библиотек zapret2 (`/opt/zapret2/lua/…`) и имена блобов (`fake_default_tls`).

### 3. ByeDPI (ciadpi) — SOCKS-обход DPI (опционально)
- Проверено: **0.17.3** (последний выпуск 2025-09-22; проект в основном стабилен).
- Сервис запускает `ciadpi -i 127.0.0.1 -p 1080 <стратегия>`; маршрутизация секций `provider: byedpi` идёт на этот порт через sing-box.

### 4. Xray-core — источник форматов узлов
- Проверено: **26.10.21** (26.10.10 и 26.10.17 отозваны из-за убранных корневых сертификатов; 26.10.21 собран с Go 1.27.3 — обновлять обязательно). Формат ссылок проверен на 26.3.27. Xray не запускается сервисом; ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `hy2://` разбираются и превращаются в узлы sing-box.
- Влияние: новые транспорты (xhttp/splithttp) не имеют аналога в sing-box, такие узлы пропускаются с предупреждением. Если понадобится поддержка — отдельный провайдер (запуск xray как SOCKS-аутбаунда, как ByeDPI).

## Как проводится обновление
1. `scripts/check-upstream.sh` (или issue от workflow `Upstream`) показывает новую версию.
2. Читаются заметки выпуска (`gh release view <tag> -R <repo>`), выписываются изменения, влияющие на сгенерированный конфиг и параметры запуска.
3. Проверка: `go test ./...`, `sing-box check -c` на сгенерированном конфиге (job `nft-syntax` и тесты билдера), проверка на роутере (`hydravpn-router selftest`).
4. Правка `docs/components.tsv`, `internal/components` (`Tested`), `Dockerfile` (`SING_BOX_IMAGE`), CHANGELOG.
